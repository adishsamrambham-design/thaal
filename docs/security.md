# Security plan

The guiding rule is that **the database decides who can see what**, not the screen. The app can have bugs; Row Level Security (RLS) is the last line of defence.

| #   | Risk                               | Impact                                  | Control                                                                                                                                                                 | How it's tested                                                             |
| --- | ---------------------------------- | --------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| 1   | Private draft read by another user | Leaked manuscript, loss of author trust | RLS: `works`/`chapters` readable only by owner unless `status='published'`; private storage buckets; drafts never cached publicly                                       | SQL tests run as user A, B and anonymous; Playwright test tries direct URLs |
| 2   | Paid chapter read without purchase | Lost author income                      | Paid chapter body lives in a table the client **cannot select**; served only through a server function that checks `entitlements`; comic pages via 5-minute signed URLs | Tests with and without entitlement; tampered IDs                            |
| 3   | Fake payment success               | Free books, wrong payouts               | Entitlement only after server-side HMAC signature verification + webhook; webhook signature verified; idempotency keys; never trust client callbacks                    | Unit tests with valid, invalid and replayed signatures                      |
| 4   | Money calculation errors           | Over- or under-paying authors           | Integer paise only; one tested split function; append-only double-entry ledger; DB constraint that every transaction balances; daily reconciliation                     | Property tests (thousands of random prices), ledger balance checks          |
| 5   | Leaked secrets                     | Account takeover, data loss             | Env vars validated at startup; service-role key used only server-side and never shipped to the browser; secret scanning in CI; `.env*` gitignored                       | CI check fails on the service key in client bundles                         |
| 6   | Account takeover                   | Drafts and earnings stolen              | Supabase Auth, magic link + Google; rate limits; re-confirm before changing payout bank details                                                                         | —                                                                           |
| 7   | Malicious content (XSS via editor) | Stealing readers' sessions              | Store editor JSON, render through an allow-list of nodes; no raw HTML; strict Content-Security-Policy                                                                   | Tests with script-injection payloads                                        |
| 8   | Malicious uploads                  | Malware, huge files                     | Type and size limits; images re-encoded on upload; no SVG uploads                                                                                                       | —                                                                           |
| 9   | AI credit abuse                    | API bills                               | Credits deducted **before** the call in a transaction, refunded on failure; per-user rate limits; hard monthly spend cap                                                | Concurrency test for double-spend                                           |
| 10  | Abuse, piracy, illegal content     | Legal risk                              | Report button, moderation queue, takedown workflow, grievance contact (IT Rules)                                                                                        | —                                                                           |

**Honest limits:** No website can stop a paying reader from screenshotting or retyping a book. We make bulk copying inconvenient and watermark comic pages with the buyer's ID, but we don't promise DRM.

**Privacy:** India's DPDP Act applies. We collect the minimum (email, display name, and payout KYC only through the payment provider, never stored by us). Data export and deletion will be built. A lawyer must review the privacy notice.
